# Tether 0.4.0 (release 22 nov 2026)

**Run agents you don't trust on infrastructure you do.**

Tether wraps an agent you already have. Every model call and tool call the agent makes goes through it, so each one is checked against your rules, counted against your budget, run in a sandbox, and written to a trace. The trace is complete enough to run the agent again from it, which is what the rest is built on: replay, diff and evals.

`tether eval` replays twenty recorded tasks, then asks them again under a changed prompt and reports which fail and why. Twenty tasks were recorded once against a real model. `tether eval` checks the recordings against assertions at no cost, then asks the same tasks again under a changed prompt. One now fails: the agent tried `rm`, policy refused it, and the table names the rule.

## Integración: dos puntos de llamada

Tether no depende de cómo esté escrito tu agente. Necesita los dos puntos donde el agente toca el mundo: donde pregunta al modelo y donde ejecuta una herramienta.

```python
import tether

with tether.Run(policy="tether.toml") as run:
    messages = [tether.user("Fix the failing test.")]
    while True:
        reply = run.complete(model="claude-opus-5-5", messages=messages)  # llamada al modelo
        messages.append(reply.message)
        results = [run.call_tool(call) for call in reply.tool_calls]      # llamadas a herramientas
        if not results:
            break
        messages.append(tether.tool_results(results))
    run.finish(reply.text)
```

El bucle es tuyo. Las reglas están en `tether.toml`:

```toml
[budget]
max_usd = 5.00
max_tool_calls = 400

[[rule]]
name = "write-src"
match = { tool = "sandbox.write_file", path = "src/**" }
action = "allow"

[[rule]]
name = "no-rm"
match = { tool = "sandbox.exec", argv0 = "rm" }
action = "deny"
reason = "deleting files is off limits in this run"
```

Una regla permite, deniega o pregunta a una persona. Todo lo que ninguna regla cubre se pregunta. Un presupuesto agotado detiene la ejecución, y una ejecución detenida puede reanudarse.

## Distinción clave documentada

Una reproducción puede reutilizar respuestas grabadas sin volver a llamar al modelo, pero cambiar el modelo o el prompt puede exigir llamadas nuevas en cuanto la ejecución diverge. Una ejecución grabada tampoco puede mostrar qué habría hecho el agente tras una acción denegada bajo las reglas originales. Por eso Tether sirve para comprobar si un cambio de política habría bloqueado una acción en una ejecución conocida antes de probarlo en vivo. **No demuestra que el agente se comporte igual en una tarea nueva.**

## Comandos

- `tether inspect` — imprime una traza en forma legible.
- `tether verify` — comprueba la cadena de hashes de una traza y que cada payload almacenado está presente.
- `tether replay` — reproduce una traza desde la grabación: sin red, sin coste. Bajo una política cambiada, muestra qué habría decidido esa política.
- `tether diff` — muestra dónde divergen dos ejecuciones.
- `tether eval` — reproduce un conjunto de tareas grabadas bajo un prompt/modelo nuevos o comprueba cada una contra aserciones.
- `tether ui` — traza en el navegador, con rechazos, preguntas y paradas marcados.

## Detalles técnicos

Tether es un arnés en Rust; usa reproducciones deterministas desde trazas JSONL append-only para permitir pruebas de coste cero de cambios de política, prompts y modelos. Almacena historiales de mensajes y resultados grandes de herramientas como blobs direccionados por contenido (BLAKE3) y trata los timestamps por emparejamiento de contrapartes, permitiendo reproducción exacta evento a evento hasta que se produce una divergencia.
