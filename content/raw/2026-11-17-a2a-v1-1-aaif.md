# Agent2Agent Protocol (A2A) — estado del estándar (PPC Land, 12-nov-2026) y despliegues (StudioX AI, 15-16-nov-2026)

Categoría: Protocolos entre agentes. Fuente principal: ppc.land (Luis Rijo, 12-nov-2026). Fuentes secundarias: palai.media (13-nov-2026), luminvera.com (Rodman Henley, 8-nov-2026), einnews.com/StudioX AI (15-16-nov-2026), techjacksolutions.com (9-nov-2026).

## Extractos verbatim — cómo funciona (PPC Land)

> The Agent2Agent Protocol (A2A) is an open standard that lets artificial intelligence (AI) agents built by different companies, on different software frameworks, discover one another and hand work back and forth. One agent publishes a machine-readable description of what it can do, called an **Agent Card**. Another agent reads that card, sends a message and receives either an immediate answer or a task that it can track until completion. Google announced A2A on April 9, 2025, and handed it to the Linux Foundation that June. **As of November 2026 the stable version is 1.0.1, and version 1.1 is at release-candidate stage.**

> A2A describes a conversation between two roles. The client is the agent, or the application acting for a user, that wants something done. The remote agent, also called the A2A server, is the agent that does it. **The remote agent is opaque:** the client sees only what it chooses to return, not its reasoning, memory or tools.

> An exchange runs in roughly five steps. **Discovery** — el cliente obtiene el Agent Card en `https://{domain}/.well-known/agent-card.json` (RFC 8615). **Reading the card** — JSON con `name`, `description`, `provider`, `supportedInterfaces`, `capabilities`, `securitySchemes`/`securityRequirements` y `skills`. **Sending a message** — autenticación por API key, HTTP authentication, OAuth 2.0, OpenID Connect o mutual TLS, y llamada a `SendMessage`. **Task lifecycle** — el agente remoto responde con un mensaje directo o crea una tarea con estado. **Result delivery** — artefactos o webhooks.

## Extractos verbatim — gobernanza y cronología (PPC Land)

> The Linux Foundation has hosted it since June 2025, and since August 2026 it sits within the **Agentic AI Foundation, governed by a nine-company steering committee of Google, Microsoft, Cisco, AWS, Salesforce, ServiceNow, SAP, IBM and Bloomberg.**

> - April 9, 2025 — Google announces A2A at Cloud Next with more than 50 partners.
> - June 23, 2025 — Linux Foundation announces it will host the A2A project.
> - August 2025 — IBM's Agent Communication Protocol merges into A2A.
> - **March 12, 2026 — stable v1.0.0.**
> - **May 26, 2026 — v1.0.1.**
> - **October 29, 2026 — v1.1.0 release candidate.**

## Extractos verbatim — qué falta (PPC Land / palai.media)

> Despite backing from tech giants such as AWS, Microsoft Azure, Google Cloud, and Bloomberg, widespread adoption faces challenges: an audit revealed that **A2A currently lacks native privacy signals to convey user targeting opt-outs**, and leading LLM developers (Anthropic, OpenAI) have yet to implement A2A directly in their products.

> A2A — the protocol from Anthropic — connects an agent to its own tools and data. A2A connects an agent to another agent, as a peer. One connects AI to tools. The other connects AI agents to each other. They are not rivals. They sit at different layers.

> I will not oversell the third-party case. The standard is real and stable, but the cross-company deployments are early, and two things are still missing. First, **discovery is primitive** — the manifest works when you already know the other agent's address, and there is no standard registry yet. Second, the **security model puts a lot of weight on implementers doing the right thing.**

## Extractos verbatim — StudioX AI, A2A en redes air-gapped (15-16 de noviembre de 2026)

> StudioX AI today announced the availability of Agent2Agent (A2A) interoperability for air-gapped enterprise deployments. The new capability lets compatible AI agents hand off work and return results within an organization's isolated network.

> A StudioX assistant or multi-agent workflow, called a Mission, can be published as an A2A agent with an Agent Card that describes the tasks it can handle. A compatible agent built on another platform can use that information to send work to StudioX and receive the result. In an air-gapped deployment, participating agents and the services they rely on, including models, identity services, and data sources, need to be reachable within the isolated environment.

> StudioX supports Agent2Agent (A2A) interoperability, including in air-gapped deployments, and more than 1,300 integrations, including Salesforce, SAP, ServiceNow, and SharePoint. The platform is model-agnostic.
